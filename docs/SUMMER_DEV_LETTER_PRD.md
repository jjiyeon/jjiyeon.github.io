# Summer's Dev Letter PRD

## 1. 프로젝트 요약

`jjiyeon.github.io`를 **Summer's Dev Letter**라는 개인 개발자 사이트로 전환한다.

사이트의 중심은 두 가지다.

- `Letters`: 매주 남기는 개발레터 아카이브
- `About`: 이력서 기반으로 Summer의 경험과 강점을 설명하는 페이지

전체 인상은 조용하고 단순한 개인 기록 저장소에 가까워야 한다. 개발레터는 시간이 지나며 Summer가 어떻게 생각하고 일하는지 보여주고, About은 이력과 프로젝트, 강점이 한눈에 정리되는 포트폴리오 역할을 한다.

## 2. 목표

이 사이트는 방문자가 다음 질문에 답할 수 있게 만드는 것이 목표다.

> Summer는 어떤 개발자이고, 일하면서 어떤 방식으로 생각하는가?

이력서만으로는 드러나기 어려운 판단 기준, 협업 방식, 문제를 정리하는 습관을 개발레터와 About을 통해 보여준다.

## 3. 제품 방향

이 사이트는 일반적인 기술 블로그가 아니다.

다음 세 가지 역할을 함께 가진다.

- 뉴스레터: 각 글은 한 주의 흐름과 생각이 정리된 한 편의 개발레터다.
- 월별 아카이브: 지난 글은 월, 주차, 카테고리 기준으로 쉽게 훑을 수 있어야 한다.
- 포트폴리오 신호: About과 Letters가 함께 Summer의 경험, 판단력, 일하는 방식을 보여준다.

## 4. 주요 방문자

- Summer의 일하는 방식을 알고 싶은 사람
- 프론트엔드, 제품 사고, 협업, 성장에 관심 있는 개발자
- 이력서보다 조금 더 입체적인 정보를 보고 싶은 채용 담당자나 협업자

## 5. 콘텐츠 모델

개발레터 한 편은 Markdown 파일 하나로 관리한다.

권장 경로:

```txt
src/content/letters/
  2026/
    05/
      week-1/
        index.md
        cover.jpg
        inline-note.png
      week-2/
        index.md
        cover.jpg
```

개발레터 상세 URL:

```txt
/letters/2026-05-week-1
```

월별 아카이브 URL:

```txt
/letters/2026/05
```

## 6. 개발레터 Frontmatter

```md
---
title: "2026년 5월 1주차 개발레터"
subtitle: "일을 정리하는 방식에 대해 생각한 한 주"
letterSlug: "2026-05-week-1"
publishedAt: "2026-05-03"
week: "2026-W18"
issue: 1
category: "work"
tags:
  - collaboration
  - retrospective
  - frontend
summary: "이번 주에는 개발 기록을 어떻게 나답게 쌓을지 고민했다."
cover: "./cover.jpg"
coverAlt: "개발레터 대표 이미지 설명"
status: "published"
---
```

Astro는 content entry routing metadata로 `slug`를 예약해서 사용하므로, 공개 URL에 사용할 값은 `letterSlug`에 둔다.

레터 대표 이미지와 본문 이미지는 해당 레터 폴더 안에서 함께 관리한다.

- `cover.jpg`: Letters 목록과 상세 상단에서 사용하는 대표 이미지
- `inline-*.png`: 본문 안에 삽입하는 이미지

본문 이미지는 Markdown에서 상대 경로로 참조한다.

```md
![작업 흐름을 정리한 다이어그램](./inline-flow.png)
```

## 7. 개발레터 본문 템플릿

```md
## 이번 주의 한 줄

이번 주를 관통한 생각을 한 문장으로 적는다.

## 한 일

- 무엇을 만들었는지
- 어떤 문제를 해결했는지
- 어떤 결정을 했는지

## 생각한 것

일하면서 생긴 판단, 의문, 기준을 정리한다.

## 배운 것

기술적으로 배운 점, 다음에 다르게 할 점을 쓴다.

## 남겨둘 조각

짧은 메모, 읽은 글, 인상 깊은 문장, 다음 주에 이어갈 질문을 적는다.
```

## 8. 정보 구조

```txt
/
  최신 월 Letters 화면

/letters
  최신 월 Letters 화면

/letters/[year]/[month]
  한 달치 개발레터를 주차별로 보여주는 월별 아카이브
  카테고리 필터 포함

/letters/[slug]
  개발레터 상세 페이지

/about
  프로필 이미지, 이력, 프로젝트, 강점, 현재 관심사를 담은 이력서 기반 페이지
```

상단 내비게이션에는 다음 두 메뉴만 둔다.

```txt
Letters
About
```

왼쪽 브랜드/로고 영역은 나중에 로고를 넣기 위해 공간만 남기고, 지금은 시각적으로 비워둔다.

## 9. 초기 카테고리

- `work`: 일하는 방식, 협업, 커뮤니케이션
- `dev`: 개발, 구현, 디버깅, 아키텍처
- `product`: 제품 사고, 사용자 경험, 기획
- `career`: 성장, 커리어, 회고
- `notes`: 짧은 생각, 읽은 글, 작은 배움

카테고리는 처음에는 제한적으로 유지한다. 태그는 frontmatter에 둘 수 있지만, 첫 디자인 개편에서는 주요 탐색 메뉴로 사용하지 않는다.

## 10. MVP 범위

MVP에 포함한다.

- Astro 정적 사이트 구성
- Markdown 기반 개발레터
- `Letters`, `About`만 있는 최소 상단 내비게이션
- 월별 탐색 중심의 Letters 화면
- 개발레터 상세 페이지
- 주차별 개발레터 목록
- Letters 내부 카테고리 필터
- 프로필 이미지와 이력서 기반 섹션을 가진 About 페이지
- SEO 메타데이터
- RSS 피드
- GitHub Actions 기반 GitHub Pages 배포

첫 버전에서 제외한다.

- 관리자 에디터
- 로그인
- 댓글
- 분석 대시보드
- 복잡한 검색
- 독립적인 카테고리 인덱스 페이지
- 독립적인 태그 페이지

## 11. 디자인 방향

사이트는 미니멀하고 조용하며, 이력서와 함께 보기 좋은 포트폴리오 감각을 가져야 한다.

피한다.

- 일반적인 SaaS 랜딩 페이지 스타일
- 카드만 빽빽하게 나열한 블로그 레이아웃
- 지나치게 기술 문서처럼 보이는 스타일
- 콘텐츠 정체성과 관계없는 장식 요소
- 로고가 준비되기 전의 과한 헤더 브랜딩

선호한다.

- `Letters`, `About` 두 메뉴만 있는 단순한 구조
- 월별 캘린더/아카이브처럼 느껴지는 Letters 페이지
- 뉴스레터처럼 읽히는 상세 페이지
- 빠르게 훑을 수 있는 희박하고 정돈된 목록
- 깔끔한 포트폴리오/이력서 레이아웃을 참고하되 Summer만의 콘텐츠 구조를 가진 About 페이지
- 강한 장식보다 좋은 타이포그래피와 절제된 여백

### 데스크탑 방향

Letters는 2열 구조를 사용한다.

- 왼쪽 영역: 현재 월, 강조된 주차, 월 이동, 카테고리 필터
- 오른쪽 영역: 한 달의 개발레터 4-5개를 보여주는 스크롤 가능한 목록
- 페이지네이션은 글 단위가 아니라 월 단위로 이동한다.

About은 프로필 중심으로 시작한다.

- 상단에 원형 프로필 이미지
- 이름, 역할, 짧은 소개, 링크
- Work, Projects, Expertise, Now 같은 이력서형 섹션

### 모바일 방향

모바일에서는 데스크탑 사이드바를 그대로 유지하지 않는다.

- 상단 내비게이션은 `Letters`, `About`만 유지한다.
- Letters는 월 제목, 월 이동, 가로 스크롤 카테고리 칩, 주차별 레터 목록 순서로 쌓는다.
- About은 프로필 이미지, 요약, 이력서형 섹션을 세로로 쌓는다.

## 12. 기술 방향

이 사이트는 콘텐츠 중심의 정적 사이트이므로 Astro를 사용한다.

권장 스택:

- Astro
- TypeScript
- Markdown content collection
- Plain CSS 또는 Astro scoped style
- GitHub Actions
- GitHub Pages

`jjiyeon.github.io` 저장소는 사용자/조직 페이지 패턴이므로 Astro 설정에는 `site`만 지정하고 `base`는 두지 않는다.

```js
export default defineConfig({
  site: 'https://jjiyeon.github.io',
});
```

## 13. 마이그레이션 계획

### Phase 1. 계획 정리

- PRD와 실제 구현 계획을 정리한다.
- 핵심 구조와 콘텐츠 모델을 확정한다.
- 첫 버전은 Markdown 기반으로 시작한다.

### Phase 2. Astro 기반 전환

- 기존 Jekyll 구조를 제거하거나 대체한다.
- Astro 프로젝트 구조를 추가한다.
- 공통 레이아웃과 전역 스타일을 추가한다.
- 개발레터 content collection schema를 만든다.

### Phase 3. 핵심 페이지

- 최신 월 Letters 화면을 만든다.
- 월별 Letters 아카이브를 만든다.
- 개발레터 상세 페이지를 만든다.
- About 페이지를 이력서 기반으로 만든다.

### Phase 4. 발행 흐름

- 첫 샘플 개발레터를 추가한다.
- 재사용 가능한 개발레터 템플릿을 추가한다.
- RSS 피드를 추가한다.
- GitHub Pages workflow를 추가한다.
- production build를 검증한다.

### Phase 5. 디자인 개편

- 데스크탑 2열 Letters 레이아웃을 다듬는다.
- 모바일 단일 컬럼 레이아웃을 다듬는다.
- About 프로필/이력서 섹션을 다듬는다.
- SEO 메타데이터와 RSS를 재검토한다.
